How ScaleLink Handles High-Concurrency (System Design Walkthrough)

1. KGS Range Allocation

Instead of doing slow DB row increments, pods atomically reserve blocks of 10,000 IDs with pessimistic row locks (SELECT FOR UPDATE). 9,999 out of 10,000 requests are served in-memory.

2. Bloom Filter Negative Barrier

Malicious bot crawlers requesting random non-existent URLs are stopped cold at memory layer. If Guava Bloom Filter says NO, it's 100% not in DB—saving thousands of wasted Postgres connections.

3. Async Batch Telemetry

HTTP 302 redirects are sent back to the browser immediately (<5ms). Telemetry is dropped into a bounded ring buffer and flushed in batches of 200 via Java 21 Virtual Threads.
